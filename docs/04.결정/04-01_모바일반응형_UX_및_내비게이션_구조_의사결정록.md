# 04-01. 모바일 반응형 UX 및 3대 도메인 내비게이션 구조 의사결정록 (ADR)

## 🎯 1. 개요 및 의사결정 배경

purePDFrend 서비스의 지속적인 기능 확장으로 상단 메뉴가 8개 뷰로 증가함에 따라 사용자의 인지 과부하가 발생하고, 768px 미만 모바일 뷰포트에서 레이아웃 깨짐(가로 오버플로우) 및 작은 터치 타깃으로 인한 오작동이 확인되었습니다.
이에 따라 프로젝트의 표준 의사결정 절차에 입각하여 핵심 3대 쟁점에 대한 대안을 비교 평가하고 최적의 추천안을 채택하였습니다.

---

## ⚖️ 2. 3대 핵심 의사결정 항목 및 대안 비교

### [의사결정 1] 모바일 내비게이션 인터페이스 형태

* **배경**: 8대 뷰를 768px 미만 모바일 화면에서 가장 효율적으로 전환할 수 있는 내비게이션 구조 결정.
* **대안 비교**:
  1. **대안 A (하단 탭 바 - Bottom Navigation Bar)**:
     - *장점*: 엄지손가락 접근성 우수.
     - *단점*: 화면 하단 영역을 상시 점유하여 문서 뷰어 공간 축소. 최대 4~5개 메뉴만 수용 가능하여 '더보기' 팝업 등 이중 뎁스 강제.
  2. **대안 B (우측 슬라이딩 오프캔버스 드로어 + 상단 퀵 칩 바 하이브리드)** [채택]:
     - *장점*: 상단 가로 스와이프 퀵 칩 바로 자주 쓰는 8대 뷰를 1-Tap 즉시 전환. 슬라이딩 드로어를 통해 3대 도메인 체계 및 시스템 상태를 체계적으로 확인 가능. 본문 작업 공간 최대 확보.
     - *단점*: 드로어 오픈 시 1회 추가 탭 발생 (단, 상단 퀵 칩 바로 상쇄).
  3. **대안 C (헤더 아코디언 드롭다운)**:
     - *장점*: 구현 복잡도 낮음.
     - *단점*: 메뉴 확장 시 메인 콘텐츠를 아래로 밀어내어 시각적 안정성 저하.
* **👉 최종 결정: [대안 B] 우측 슬라이딩 드로어 + 상단 퀵 칩 바 채택**
* **영향도**: `Navbar.tsx`에 모바일 56px 헤더, 퀵 칩 바, 슬라이딩 드로어 모달 컴포넌트 추가.

---

### [의사결정 2] 데스크톱 3대 도메인 메뉴 인터랙션 방식

* **배경**: 상단 대메뉴 선택 시 8대 하위 뷰 접근 인터랙션 방식 결정.
* **대안 비교**:
  1. **대안 A (마우스 호버 Hover 드롭다운)**:
     - *장점*: 클릭 수 최소화.
     - *단점*: 마우스 이탈 시 메뉴가 깜빡이며 닫히는 UX 결함 발생, 터치스크린 탑재 노트북에서 오동작.
  2. **대안 B (원클릭 Click 도메인 선택 + 활성 도메인 서브 퀵 바)** [채택]:
     - *장점*: 클릭 기반의 명확한 상태 전이. 현재 작업 중인 도메인의 하위 뷰가 서브 바에 안정적으로 노출되어 맥락 유지 탁월. 데스크톱/태블릿 완벽 호환.
     - *단점*: 서브 퀵 바로 인해 세로 36px 추가 점유 (담백한 미니멀 스타일로 상쇄).
  3. **대안 C (단일 셀렉트 드롭다운 박스)**:
     - *장점*: 헤더 공간 절약.
     - *단점*: 전체 서비스의 3대 도메인 구조가 은닉되어 탐색 효율성 저하.
* **👉 최종 결정: [대안 B] 원클릭 도메인 탭 + 서브 퀵 바 채택**
* **영향도**: 3대 도메인과 8대 뷰가 시각적 위계에 따라 2단으로 명확히 배치되어 인지 과부하 100% 해소.

---

### [의사결정 3] 모바일 뷰포트 내 광폭 데이터 테이블/차트 처리 전략

* **배경**: 작업그래프, 트레이스 로그 테이블, 기술문서 목록 등 800px 이상의 광폭 콘텐츠의 모바일 대응 방식.
* **대안 비교**:
  1. **대안 A (모바일 전용 카드 리스트로 전면 대체)**:
     - *장점*: 가로 스크롤 없음.
     - *단점*: 모든 컴포넌트의 모바일용 뷰 코드를 별도 작성해야 하여 코드량 2배 증가 및 유지보수 파편화.
  2. **대안 B (반응형 가로스크롤 래퍼 `overflow-x-auto` + 터치 힌트 격리)** [채택]:
     - *장점*: 기존 컴포넌트 구조 100% 재사용, 테이블 컬럼 정렬 비교성 유지, 페이지 전체 가로 스크롤 완벽 방어.
     - *단점*: 사용자가 해당 데이터 영역을 좌우로 스와이프해야 함.
  3. **대안 C (화면 줌 축소 Scale)**:
     - *장점*: 데스크톱 레이아웃 유지.
     - *단점*: 모바일에서 텍스트 판독 불가.
* **👉 최종 결정: [대안 B] 반응형 가로스크롤 격리 래퍼 채택**
* **영향도**: 메인 컨테이너 및 각 컴포넌트 테이블 영역에 `overflow-x-auto`를 표준 래퍼로 적용하여 화면 이탈 차단.
