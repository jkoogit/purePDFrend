## 1. 배경 및 문제 정의 (Context & Problem Statement)

AI 코딩 에이전트가 복잡한 PDF 렌더링, OCR 교정, 다국어 처리 등 대규모 태스크를 수행할 때 다음과 같은 치명적인 한계가 반복적으로 발생하였습니다:
1. **작업 단절 및 먹통(Hang/Freeze) 현상**: 대화 턴, 루프, 태스크가 진행되면서 컨텍스트 윈도우가 누적되고, 예고 없이 `RESOURCE_EXHAUSTED` (429) 토큰 한도 초과 오류가 발생하여 작업이 영구 중단되는 문제.
2. **단순 글자 수 기반 토큰 계산의 비현실성**: 영문, 한글(조합형 UTF-8), 코드 블록, 마크다운 등의 토큰 소모율 차이와 LLM 모델별(Gemini, Claude, GPT) 토크나이저 가중치 차이를 반영하지 못해 오차가 누적됨.
3. **학습 및 보정 루프의 부재**: 한 번 설정된 정적 예산(Budget)을 맹신함으로써, 프로젝트가 진행될수록 예측치와 실제 소모량 간의 괴리가 커짐.
4. **기계적 반복 작업에 따른 불필요한 토큰 낭비**: 수백 줄에 달하는 터미널 헬스체크 출력이나 Git 브랜치/커밋 조회 같은 기계적 텍스트를 LLM 프롬프트에 그대로 노출하여 턴당 1,500~3,000 토큰이 무의미하게 소모됨.
5. **작업 인계 시 컨텍스트 유실**: 세션이 중단되거나 연장될 때 이전 세션의 Git 커밋 상태와 미완료 백로그가 소실되어 재작업 비용이 발생함.

## 3. 핵심 의사결정 사항 (Decision Outcome)

### [결정 3.1] 4계층 실시간 텔레메트리 연산 엔진 도입
에이전트의 매 대화 턴마다 다음 4대 지표를 실시간 계산하여 연료 게이지(Burnout Gauge)로 노출합니다:
1. **소모 속도 ($v$, Burn Rate Velocity)**: 최근 3턴의 토큰 소모 가중 평균값에 현재 세션의 보정 가중치 $\alpha$를 곱하여 산출.
   $$v = \text{avg}(\text{recent 3 turns}) \times \alpha$$
2. **버스트 스코어 ($B$, Burst Score)**: 최근 평균 대비 현재 턴의 급증 비율. $B \ge 1.5$ 이상 시 순간 폭증 경고 발령.
   $$B = \frac{\text{Current Turn Tokens}}{\text{avg}(\text{recent 3 turns})}$$
3. **루프 안전 마진 ($LSM$, Loop Safety Margin)**: 1루프당 통상 3턴 소비(안전율 1.5배) 가정 하에, 현재 잔여 토큰으로 완주 가능한 루프 수 정량 산출.
   $$LSM = \frac{\text{Remaining Tokens}}{\max(3000, v \times 3 \times 1.5)}$$
4. **소진 위험 지수 ($BRI$, Burnout Risk Index)**: 세션 기본 예산 대비 누적 소비량을 0~100%로 정규화.
   - `SAFE` ($BRI < 70\%$): 정상 진행
   - `CAUTION` ($70\% \le BRI < 85\%$): 잔여 루프 마진 모니터링 및 기계적 작업 축소
   - `CRITICAL` ($BRI \ge 85\%$): 즉시 신규 작업 차단 및 무손실 세션 인계 도시에 생성 유도

### [결정 3.2] 지수이동평균(EMA) 기반 자가 적응형 스코어카드
- 세션 종료(`#세션정리`) 시점에 총 소비량과 예측량 간의 **MAPE(절대 백분율 오차)**를 평가합니다:
  $$\text{MAPE} = \left| \frac{\text{Actual} - \text{Predicted}}{\text{Actual}} \right| \times 100$$
- 다음 세션에 상속할 보정 계수 $\alpha_{t+1}$을 적응형 학습률 $\eta = 0.15$로 자동 갱신합니다:
  $$\alpha_{t+1} = \text{clamp}\left(0.6, 2.0, \alpha_t \times \left(1 + \eta \times \frac{\text{Actual} - \text{Predicted}}{\text{Actual}}\right)\right)$$
- 이를 통해 세션이 거듭될수록 해당 프로젝트 작업 패턴에 최적화된 토큰 예측 정확도를 달성합니다.

### [결정 3.3] Git 3대 기준점 기반 무손실 세션 인계 도시에 (Handover Dossier)
- 토큰 임계치 도달 시 작업 유실을 방지하기 위해 다음 3대 기준점을 자동 스냅샷합니다:
  - `base_ref`: 세션 시작 시점의 원격 `dev` 최신 커밋 SHA (불변 기준 원점)
  - `task_checkpoint_ref`: 직전 완료 태스크의 Git 트리/커밋 SHA
  - `current_branch`: 진행 중인 작업 브랜치명
- 미완료 백로그 목록과 차기 세션에서 복사-붙여넣기로 즉시 착수 가능한 `resume_prompt`를 포함한 불변 인계 토큰(`HANDOFF-xxxx`)을 발급합니다.

### [결정 3.4] 선별적 기계적 반복 작업의 내부 API 오프로딩 (E-기능)
- 인지적 판단과 문맥이 중요한 코드 작성/리뷰는 LLM이 전담하도록 보존합니다.
- 반면, 수백 줄의 터미널 헬스체크 출력은 **터미널 압축기(Terminal Output Condenser: E-기능)**를 통해 1줄 요약문으로 압축(`[HEALTHY] 14 checks passed, 0 failures`)하여 프롬프트 토큰을 90% 이상 절약합니다.
- Git 변경사항 반영은 프롬프트에 diff를 장황하게 쓰는 대신 `scripts/github_sync_push.ts` 내부 서비스로 오프로딩합니다.

## 4. 기대 효과 및 도입 성과 (Expected Outcomes)

1. **토큰 고갈로 인한 작업 먹통(Hang/Freeze) 0건 달성**: $BRI \ge 85\%$ 시 안전 정지 및 인계 절차가 동작하여 세션 중단으로 인한 코드 소실을 원천 차단.
2. **턴당 기계적 토큰 소모량 85% 이상 절감**: 터미널 출력 압축 및 Git Data API 오프로딩을 통해 반복 턴당 평균 2,000토큰 절감.
3. **자가 적응형 예측 정확도 개선**: 초기 세션 MAPE 25% 수준에서 3회 이상 세션 누적 시 MAPE 10% 미만으로 수렴.
4. **원클릭 세션 연장 UX**: 부모-자식 세션 간 계보가 추적되며 새 세션 시작 시 1초 만에 작업 상태 완벽 복원.
