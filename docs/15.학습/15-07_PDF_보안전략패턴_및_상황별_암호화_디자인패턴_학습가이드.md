## 1. 개요 및 설계 문제의식

### 1-1. 기존 문제점: 경직된 단일 보안 정책의 한계
단순하게 "PDF 암호화 기능"을 구현할 경우 흔히 발생하는 실수는 다음과 같습니다:
- 소스 코드 내부에 하드코딩된 단일 암호화 알고리즘 (예: AES-128 고정)
- 상황(공개 논문, 사내 회의록, 유료 도서 DRM)에 따른 유연한 정책 전환 불가
- 8대 세부 권한 플래그(인쇄, 수정, 복사, 주석, 양식 필드, 접근성 등)가 비트마스크로 얽혀 있어 버그 발생 및 유지보수 난항

### 1-2. 해결책: 실전 디자인 패턴의 유기적 결합
purePDFrend에서는 이러한 운영상의 문제를 극복하기 위해 **4대 핵심 디자인 패턴**을 도메인 주도 설계(DDD) 및 헥사고날 아키텍처와 결합하였습니다.

```mermaid
graph LR
    Client[클라이언트 / PDF 관리 설정] -->|프로필 지정| Factory[PdfSecurityStrategyFactory]
    Factory -->|선택된 전략 인스턴스 반환| Strategy[IPdfSecurityStrategy]
    Strategy -->|안전한 정책 조립| Builder[PdfSecurityPolicyBuilder]
    Builder -->|불변 객체 생성| Policy[PdfSecurityPolicy & PdfPermissions VO]
    Policy -->|원스톱 오케스트레이션| Facade[PdfSecurityFacade]
    Facade -->|ISO 32000-1 키 유도 및 암복호화| Crypto[PdfCipherEngine & KeyDerivationEngine]
```

## 2. 4대 디자인 패턴 상세 해설

### 2-1. 전략 패턴 (Strategy Pattern: `IPdfSecurityStrategy`)
- **목적**: 상황(문서 배포 목적)에 따른 알고리즘 및 보안 규칙을 런타임에 유연하게 교체할 수 있도록 캡슐화합니다.
- **적용 사례**:
  1. `NoSecurityStrategy`: 공개 배포용, 암호화 비용 0, 모든 권한 개방.
  2. `ReadOnlyDistributionStrategy`: 열람 및 기본 인쇄는 허용하되, 복제 및 변조 차단.
  3. `HighConfidentialEnterpriseStrategy`: 기업 대외비용 AES-256 금융급 암호화, 듀얼 암호 체계.
  4. `StrictDRMProtectionStrategy`: 모든 권한(인쇄/복사/조합/양식) 차단 및 메타데이터까지 암호화.
  5. `CustomConfigurableSecurityStrategy`: 관리자가 비트마스크 단위로 커스텀 설정.

### 2-2. 팩토리 패턴 (Factory Pattern: `PdfSecurityStrategyFactory`)
- **목적**: 객체 생성 로직을 클라이언트로부터 분리하고, 새로운 보안 규격이 추가되더라도 기존 코드를 수정하지 않는 **개방-폐쇄 원칙 (OCP, Open-Closed Principle)**을 달성합니다.
- **코드 예시**:
```typescript
// 런타임에 동적으로 새로운 전략(예: 공공기관용 정부보안)을 등록 가능
PdfSecurityStrategyFactory.registerStrategy('GOV_SECURITY', new GovernmentSecureStrategy());

// 클라이언트는 프로필 키워드만으로 전략 인스턴스를 즉시 획득
const strategy = PdfSecurityStrategyFactory.getStrategy(profileType);
```

### 2-3. 빌더 패턴 (Builder Pattern: `PdfSecurityPolicyBuilder`)
- **목적**: 8대 권한 플래그와 알고리즘, 리비전, 듀얼 패스워드 등 파라미터가 많은 도메인 객체를 생성할 때 생성자 오버로딩의 혼란을 방지하고 유효성 불변식(Invariant)을 보장합니다.
- **불변식 방어 예시**:
  - `isEncrypted()`가 `true`일 때 사용자 또는 소유자 암호가 최소 1개 이상 지정되었는지 사전 검증.
  - 고해상도 인쇄(`canPrintHighQuality`) 활성화 시 기본 인쇄(`canPrint`) 플래그 자동 정합성 보정.

### 2-4. 파사드 패턴 (Facade Pattern: `PdfSecurityFacade`)
- **목적**: 복잡한 ISO 32000-1 Algorithm 2~7(MD5 50회 해싱 반복, 32바이트 패딩 연산, /O 및 /U 해시 생성, 객체별 키 유도)의 복잡성을 뒤로 숨기고, 클라이언트에게 단순하고 직관적인 단일 인터페이스를 제공합니다.

## 3. ISO 32000-1 권한 비트마스크 (`/P`) 산출 공식

PDF 표준에서 권한 플래그는 **부호 있는 32비트 정수(Signed 32-bit Integer)**로 표현됩니다.
ISO 규격에 따라 7~8번 비트와 13~32번 비트는 항상 `1`로 채워져야 하므로, 다음과 같이 비트 연산을 전개합니다:

```typescript
let mask = 0xffffffff; // 모든 비트를 1로 초기화

if (!this.canPrint) mask &= ~(1 << 2);      // Bit 3
if (!this.canModify) mask &= ~(1 << 3);     // Bit 4
if (!this.canCopy) mask &= ~(1 << 4);       // Bit 5
if (!this.canAnnotate) mask &= ~(1 << 5);   // Bit 6
if (!this.canFillForms) mask &= ~(1 << 8);  // Bit 9
if (!this.canAccessText) mask &= ~(1 << 9); // Bit 10
if (!this.canAssemble) mask &= ~(1 << 10);  // Bit 11
if (!this.canPrintHighQuality) mask &= ~(1 << 11); // Bit 12

return mask | 0; // 32비트 부호 정수 강제
```

## 4. 메타데이터 보호와의 연계 (`TASK-0014-01`)

앞선 태스크에서 구축한 `PdfMetadataBundle`(도서 서지정보, 학습 활동 및 회독 진도율)은 민감한 사용자 개인정보를 포함할 수 있습니다.
- **`/EncryptMetadata true`**: 일반 PDF 뷰어나 인덱싱 봇이 메타데이터를 열람하지 못하도록 스트림 전체를 암호화.
- **`/EncryptMetadata false`**: 본문은 암호화하되 서지 정보(제목, 저자, ISBN 등)는 공개 라이브러리 검색을 위해 노출 허용.

## 5. 학습 핵심 요약 및 테이크어웨이

1. **상황별 유연성(Contextual Flexibility)**: 보안은 일률적으로 강제하는 것이 아니라, 문서의 비즈니스 생명주기(공개 배포 vs 기업 대외비)에 맞춰 전략 패턴으로 설정 가능해야 한다.
2. **복합 패턴의 시너지**: 전략(선택) + 팩토리(탐색/등록) + 빌더(조립/검증) + 파사드(실행)가 결합될 때 최상의 도메인 표현력과 운영성을 확보할 수 있다.
3. **표준 준수와 환경 독립성**: 외부 npm 종속성에만 의존하지 않고, 순수 JS 기반 암호화 엔진(RC4, Node Crypto 폴백)을 갖춤으로써 브라우저와 서버 양쪽에서 100% 무중단 실행을 달성한다.
