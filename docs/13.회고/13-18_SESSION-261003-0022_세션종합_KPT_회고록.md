## 🔍 3. KPT 회고 (Keep, Problem, Try)

### 3-1. Keep (유지할 점)
1. **사용자 피드백에 대한 열린 수용과 즉각적인 기술 검증**:
   - "git pull dev처럼 git을 이용하면 간단하지 않아?"라는 사용자의 기술적 직관을 즉시 테스트하고, Untracked 충돌을 `reset --mixed`로 풀어냄으로써 시스템의 복잡도를 획기적으로 낮춤.
2. **Zero-Token No-LLM 요약 추출 원칙**:
   - 단순한 문자열 추출 및 요약 생성에 귀중한 LLM 쿼터를 낭비하지 않고, 정규식 기반 도메인 서비스를 적용하여 비용과 지연 시간을 모두 0으로 방어함.
3. **원격 Git Data API Push 및 3대 브랜치 SHA 일치 검증**:
   - 단순 API 호출에 의존하지 않고 `stg`와 `main`의 ref를 완벽히 정렬하여 3대 브랜치가 동일한 커밋 SHA를 가리키도록 엄격히 통제함.

### 3-2. Problem (문제점 및 한계)
1. **샌드박스 환경 특성에 대한 초기 고정관념**:
   - 컨테이너에 `.git`이 없다는 사실에 매몰되어 "Git 명령어를 쓸 수 없다"고 속단하고 Tarball API 우회로를 먼저 구축했던 점. 환경 내 설치된 툴(`git`)의 잠재력을 먼저 전수 조사하는 태도가 필요했음.

### 3-3. Try (새롭게 시도할 점)
1. **환경 초기화 스크립트의 원클릭 표준화**:
   - 새로운 브라우저 창이나 계정 전환 시 자동으로 실행되는 샌드박스 부트스트랩 스크립트에 `git init && git fetch && git reset --mixed`를 1순위로 포함시켜 수동 작업 제거.
2. **대화 턴 Reconcile 백그라운드 크론 자동화**:
   - 웹 서버 시작 시점 및 세션 정리 시점에 Reconcile API를 자동 트리거하여 DB 적재 누락을 영구 방지.
