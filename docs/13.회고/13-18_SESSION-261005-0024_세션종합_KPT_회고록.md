## 🔍 3. KPT 회고 분석 (Keep, Problem, Try)

### 🌟 Keep (지속 유지할 점)
1. **화면 본질에 집중하는 과감한 UI 군더더기 제거**:
   - 오프라인 복구 후 정리라는 명확한 사용 목적에 맞추어 불필요한 개념 설명 카드를 제거함으로써 사용자 시선 분산을 막고 생산성을 극대화함.
2. **모바일 가로 스크롤 0px (Table-to-Card) 표준화**:
   - 9개 컬럼의 데스크톱 테이블을 모바일에서 4행 세로 독립 카드로 전환함으로써, 모바일 환경에서도 한 손 조작과 완벽한 정보 가독성을 제공함.
3. **선제적 고아 소스/디렉터리 정화**:
   - 와이어프레임 체계가 확립됨에 따라 과거 시나리오설계 화면(`ScenarioDesignView.tsx`)과 인코딩 고아 폴더를 말끔히 제거하여 코드베이스 경량화와 아키텍처 명확성을 유지함.
4. **Zero-Loss 대화 턴 영속화 파이프라인의 완벽한 안정화**:
   - 10개 대화 턴 모두 응답 식별자(`#[0024-XX]`), 원문 Full-Text, 토큰 소모량이 로컬 및 DB에 누락 없이 보존됨.

### ⚠️ Problem (개선이 필요한 문제점)
1. **과거 프로토타입 화면의 장기 잔류**:
   - 와이어프레임(PG-USR, PG-ADM)으로 기능이 통합·이전되었음에도 초기 `ScenarioDesignView`가 네비게이션 탭에 남아 사용자에게 혼선을 줄 수 있었음.
   - *대응*: 향후 신규 와이어프레임 확정 시 구형 프로토타입 뷰의 즉각적인 대체 및 소스 정화 원칙 수립.
2. **복합 검색 필터 상태 추가 시 변수 중복 선언 위험**:
   - 정밀 필터링 개발 시 컴포넌트 내 상태 선언이 중복되어 린트 에러가 발생했던 이력이 있음.
   - *대응*: 필터 상태 객체를 `useReducer` 또는 단일 인터페이스 객체(`filterState`)로 통합 관리하는 패턴 권장.

1. **시스템서비스 와이어프레임(PG-ADM-01 ~ PG-ADM-16) 본격 착수**:

2. **IndexedDB 오프라인 이벤트 소싱 큐 실제 엔진 바인딩**:
