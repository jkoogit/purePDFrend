## 🏗️ 2. 변경 상세 내역

### 2.1 토큰 도메인 계층 (`src/aiagent/domain/token-quota/`)
- **`models/TokenTelemetry.ts`**:
  - 불변 Value Object로 설계. `isSafe()`, `isCaution()`, `isCritical()`, `hasBurstRisk()`, `hasEnoughMarginForLoop()` 등 비즈니스 규칙 판정 메서드 캡슐화.
- **`strategies/TokenEstimationStrategy.ts`**:
  - `ITokenEstimationStrategy` 및 `Gemini`, `Claude`, `OpenAI` 전략 분리. OCP를 준수하는 `TokenEstimationStrategyFactory` 도입.
- **`builders/HandoffDossierBuilder.ts`**:
  - Git 3대 기준점(`base_ref`, `task_checkpoint_ref`, `current_branch`), 백로그, 인계 토큰을 단계별로 조립하고 유효성을 검증하는 빌더 구현.
- **`services/SessionScorecardCalculator.ts`**:
  - 세션 종료 시 MAPE 오차율 계산, 지수이동평균(EMA) 기반 차기 보정치($\alpha$) 산출 및 내부 API 오프로딩 추천 알고리즘 캡슐화.
- **`TokenUsageEstimator.ts`**:
  - 기존 인터페이스의 100% 하위 호환성을 유지하면서 세부 처리를 도메인 부품들로 위임하는 Domain Facade 패턴 구현.

### 2.2 테스트 스위트 확장 (`tests/token_quota_domain.test.ts`)
- **Suite 1**: 언어/제공자 가중치 기반 휴리스틱 토큰 추정 검증.
- **Suite 2**: 4계층 텔레메트리 수식($v, B, LSM, BRI$) 검증.
- **Suite 3**: 자가 적응형 스코어카드 및 EMA $\alpha$ 보정치 산출 검증.
- **Suite 4**: 무손실 세션 인계 도시에(Handoff Dossier) 발급 및 프롬프트 검증.
- **Suite 5**: 하네스 자동화(GitOps 3대 기준점 & E-기능 터미널 압축기) 검증.
- **Suite 6 (신규)**: Strategy 다형성, TokenTelemetry 비즈니스 판정, Builder 체이닝, Domain Service 독립 호출 등 OOP/DDD 단위 검증.
