## 2. 주요 구현 내역 및 파일 변경점

```mermaid
flowchart TB
    subgraph Trigger [🚨 스냅샷 요청 트리거]
        REQ[긴급 Push 또는 수동 스냅샷 백업]
    end

    subgraph Dedup_Engine [🧠 SHA-256 지문 & 디둡 엔진]
        HASH[상태 정규화 키 SHA-256 지문 생성]
        CHECK{동일 해시 스냅샷 존재?}
        DEDUP[중복 생성 억제: verifyCount++, lastVerifiedAt 갱신 0ms]
        CREATE[신규 스냅샷 생성 verifyCount=1]
    end

    subgraph Rolling_Archive [📦 롤링 보관 & 2계층 복구]
        COUNT{활성 스냅샷 > 10개?}
        ARCHIVE[10개 초과분 ARCHIVED 상태 전환 & Cold 보관]
        KEEP[Active 10개 엄격 유지]
        RECOVER[#세션복구 시 1계층 Active -> 2계층 Archive 순차 탐색]
    end

    subgraph UTF8_Guard [🔤 전역 UTF-8 / NFC 가드레일]
        NFC[NFC 한글 정규화: 자모 분리 방어]
        SAFE_IO[safeUtf8Path: Windows/macOS 경로 안전 변환]
        BYTE_VALID[isValidUtf8: TextDecoder fatal 검증]
    end

    REQ --> HASH --> CHECK
    CHECK -- 일치 --> DEDUP
    CHECK -- 불일치 --> CREATE
    CREATE --> COUNT
    COUNT -- 초과 --> ARCHIVE
    COUNT -- 미초과 --> KEEP
    ARCHIVE -.-> RECOVER
    KEEP -.-> RECOVER
    UTF8_Guard -.-> Dedup_Engine
```

### 2.1 파일 변경 내역
1. **`src/aiagent/domain/token-quota/services/SessionDisasterRecoveryService.ts` (고도화)**:
   - `computeStateHash`: 세션/커밋/태스크/토큰 기반 상태 지문 생성.
   - `createDeduplicatedSnapshot`: 직전 스냅샷과 지문 일치 시 중복 파일 생성 억제 및 `verifyCount` 갱신.
   - `archiveOldSnapshots`: 활성 스냅샷 10개 롤링 보관 및 초과분 Cold Storage 전환.
   - `resolveRecoveryTarget`: 1계층(Active) ➔ 2계층(Archived Cold Storage) 순차 탐색으로 영구 복구 안전성 보장.
2. **`src/aiagent/services/Utf8EncodingGuardService.ts` (신규)**:
   - 유니코드 NFC 한글 정규화 (`normalizeNfc`)로 자모 분리 현상 원천 차단.
   - `safeUtf8Path` 헬퍼를 통한 Windows/macOS 경로 호환성 확보.
   - `isValidUtf8` 바이트 무결성 검증기.
3. **`src/aiagent/components/EmergencyRecoveryPanel.tsx` (고도화)**:
   - 스냅샷 목록에 `SHA-256 디둡` 상태 뱃지 표시.
   - 상단 헤더에 `[🧹 10건 초과 아카이빙]` 원클릭 버튼 연동.
4. **설계 및 학습 문서 작성**:
