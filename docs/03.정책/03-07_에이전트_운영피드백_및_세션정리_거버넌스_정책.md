## 1. 목적 및 배경

본 문서는 인공지능 에이전트 협업 환경에서 작업의 추적성(Traceability), 무결성(Integrity), 재현성(Reproducibility)을 극대화하기 위한 운영 피드백 반영 지침과 세션 정리(Finalize) 거버넌스 표준을 규정합니다.

---

## 2. 에이전트 운영 피드백 거버넌스 원칙

1. **채팅 시작 번호 표기 (`[0000]` 체계)**
   - 에이전트는 대화 턴 시작 시 대화 순번을 나타내는 4자리 식별 번호(`[0000]`, `[0001]`, ...)와 함께 계획된 작업 범위를 명확히 선언합니다.
2. **`#태스크처리` 선행 원칙**
   - 사용자의 명시적인 `#태스크처리` 지시가 전달되기 전에는 어떠한 소스 코드나 문서 파일도 임의로 수정하거나 생성하지 않습니다.
3. **다음작업 프롬프트 블럭 필수 제공**
   - 모든 태스크 완료 응답의 말미에는 후속 작업을 연속적으로 이어나갈 수 있도록 코드블럭 형식의 '다음 작업 프롬프트'를 필히 제공합니다.

---

## 3. 세션 정리(Finalize) 및 그룹 영속화 거버넌스

### 3.1 하네스 3계층 집계 및 그룹화 영속화
세션 종료 및 정리(`finalize`) 시 에이전트 및 백엔드 서비스는 다음 작업을 완수해야 합니다:
- **세션 메타 (`harness_session_meta.doc_payload`)**:
  - 세션에 속한 모든 태스크 목록 및 태스크별 작업그룹, 브랜치 정보를 `task_groups` JSONB로 집계하여 영속화합니다.
- **태스크 메타 (`harness_task_meta.doc_payload`)**:
  - 각 태스크에 종속된 하위 루프들의 세부 작업 내역(items), 상태를 `loop_groups` JSONB로 집계하여 저장합니다.
- **상태 전이**: 세션 및 태스크 상태를 최종 정리/승급/종료 상태로 갱신합니다.

### 3.2 대화 턴(Conversation Trace) 1:1 매핑
- 작업정보관리(`TaskInfoManager`)에서 특정 세션, 태스크, 루프를 선택할 경우 즉시 해당 대화 턴 추적 화면(`AgentUsageViewer`)으로 이동하여 상세 프롬프트와 응답 내역을 열람할 수 있어야 합니다.

### 3.3 문서 동기화 및 고아 문서 무결성
- 세션 정리 단계에서 파일 시스템의 모든 마크다운 문서와 DB의 `docs_governance` 테이블 레코드는 1:1 동기화 상태를 검증합니다.
- 파일 시스템에 없는 고아 레코드는 자동 정리되어야 하며, 고아 문서(Orphans)는 0건을 유지합니다.

## 4. 대용량 작업 노드 성능 대응 및 UI 운영 정책

1. **계층 그룹 뷰(Hierarchical Group View)**
   - 세션 그룹 > 태스크 그룹 > 루프 카드로 구성된 중첩 계층 구조를 제공합니다.
   - 표시 노드가 증가할 경우 발생하는 DOM 렌더링 부하를 완화하기 위해 **세션 그룹 단위 기본 접기/펼치기** 기능을 적용합니다.
2. **하위 활성화 집중 모드 (Downstream Focus Mode)**
   - 특정 작업 카드(세션, 태스크, 루프)를 체크/선택할 경우 해당 노드를 기준으로 종속된 하위 노드만 선명하게 강조(Highlight)하고, 무관한 상위/동일 계층 노드는 감광(Dimming) 처리하여 사용자의 컨텍스트 인지를 돕습니다.
3. **뷰 설정(비율, 간격, 레이아웃) 영속화**
   - 뷰어 옵션(컬럼 간격, 줌 확대비율, 상태 필터, 레이아웃 모드)은 DB(`harness_session_meta.doc_payload.view_state`) 및 로컬 캐시에 즉시 영속화되어 재접속 시에도 유지됩니다.
