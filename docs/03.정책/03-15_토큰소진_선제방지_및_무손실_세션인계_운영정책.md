# 03-15. 토큰 소진 선제 방지 및 무손실 세션 인계 운영 정책

> **문서 상태**: 확정 및 운영 적용 (Active)  
> **최초 작성일**: 2026-09-22  
> **소관 부서**: purePDFrend 에이전트 거버넌스 및 품질관리실  
> **상위 규정**: AGENTS.md v2.1 제5조 (데이터 거버넌스 및 토큰 소진 대응 규칙)

---

## 1. 목적 (Purpose)
본 정책은 purePDFrend 프로젝트의 AI 코딩 에이전트가 긴 호흡의 작업을 수행할 때 컨텍스트 한도 도달로 인한 예기치 못한 작업 단절(Hang/Freeze)을 원천 차단하고, 객관적인 텔레메트리 지표에 기반하여 안전하게 세션을 분할 및 인계하는 절차를 규정함을 목적으로 합니다.

---

## 2. 4계층 실시간 텔레메트리 모니터링 정책

### [규칙 2.1] 턴 단위 텔레메트리 자동 연산
모든 대화 턴의 요청 및 응답 시, 하네스 서비스(`POST /api/agent/trace/turn`)는 토큰 추정치 및 다음 4대 텔레메트리 지표를 자동 산출하여 응답에 포함해야 합니다:
1. **소모 속도 ($v$)**: 최근 3턴의 가중 평균치에 해당 세션의 보정 가중치 $\alpha$를 곱한 값
2. **버스트 스코어 ($B$)**: 최근 3턴 평균 대비 현재 턴의 급증 배율
3. **루프 안전 마진 ($LSM$)**: 잔여 가용 예산 기준 안전하게 완주 가능한 잔여 루프 수
4. **소진 위험 지수 ($BRI$)**: 현재 세션의 토큰 예산 소모율 (0~100%)

### [규칙 2.2] 단계별 소진 위험 가드레일 (BRI Guardrails)
- **`SAFE` 구간 ($BRI < 70\%$)**: 통상적인 태스크 및 루프 작업을 자유롭게 수행합니다.
- **`CAUTION` 구간 ($70\% \le BRI < 85\%$)**:
  - UI 상단 `TokenBurnoutGauge`에 황색 경고를 표시합니다.
  - 대화 턴에 장황한 설명이나 불필요한 마크다운을 억제하고 마이크로 턴으로 호흡을 단축합니다.
  - $LSM < 2$ 인 경우 신규 루프 착수를 지양하고 현재 루프의 마감에 집중합니다.
- **`CRITICAL` 구간 ($BRI \ge 85\%$)**:
  - UI 상단에 적색 경고를 점등하고 신규 태스크 생성을 즉시 차단합니다.
  - 에이전트는 즉시 작업을 정리하고 `HandoffDossier` 생성을 유도합니다.

## 3. 세션 정리 및 자가 적응형 스코어카드 산출 정책

### [규칙 3.1] 세션 종료 시 스코어카드 필수 산출
- 세션을 마감(`#세션정리`)할 때 `POST /api/agent/telemetry/scorecard`를 호출하여 세션 전체의 토큰 소비 실적을 평가합니다.
- 평가 항목: 총 턴수, 총 루프수, 실측 소비량, 예측 소비량, MAPE(절대 오차율), 차기 세션 상속 가중치 $\alpha$.
- 산출된 스코어카드는 세션 메타정보(`harness_session_meta.doc_payload.token_scorecard`)에 영구 저장됩니다.

### [규칙 3.2] 차기 세션 가중치($\alpha$) 상속 의무
- 세션 연장 또는 신규 세션 시작 시, 직전 세션에서 산출된 $\alpha$ 값을 기본 상속하여 토큰 추정 수식에 적용합니다.

## 4. 무손실 세션 인계 도시에(Handover Dossier) 운영 정책

### [규칙 4.1] Git 3대 기준점 불변 스냅샷
세션 인계 도시에 생성 시 다음 3대 Git 기준점을 필수적으로 기록하여 작업 불변성을 보장해야 합니다:
1. `base_ref`: 세션 시작 원점의 원격 커밋 SHA
2. `task_checkpoint_ref`: 태스크 착수 직전의 Git 트리 SHA
3. `current_branch`: 작업 브랜치명

### [규칙 4.2] 인계 토큰 발급 및 백로그 상속
- 인계 도시에는 `HANDOFF-[타임스탬프]-[랜덤코드]` 형식의 불변 토큰을 발급합니다.
- 현재 세션의 미완료 백로그 목록이 도시에에 자동 상속되며, 새로운 세션 착수용 프롬프트(`resume_prompt`)가 원클릭 복사 가능한 형태로 제공되어야 합니다.

## 5. 기계적 반복 작업 오프로딩 정책

### [규칙 5.1] E-기능 터미널 헬스체크 압축 의무
- 서비스 전수 점검 및 헬스체크 시 수십~수백 줄의 원시 텍스트를 LLM 프롬프트에 그대로 노출하지 않고, `HarnessAutomationService.condenseHealthCheck()`를 통해 1줄 요약문으로 압축 전달합니다.

### [규칙 5.2] 인지적 판단 업무의 API 강제 전환 금지
- 아키텍처 의사결정, 기획서 작성, 도메인 분석, 코드 리뷰 등 맥락적 사고가 필요한 영역은 일체의 기계적 API 변환을 금지하며 LLM 본연의 생성 능력을 보존합니다.
