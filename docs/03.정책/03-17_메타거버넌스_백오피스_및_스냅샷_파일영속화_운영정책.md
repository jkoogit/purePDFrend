# 메타 거버넌스 백오피스 및 세션 스냅샷 파일 영속화 운영 정책 (정책 03-17)

> **적용 대상**: AI 에이전트 하네스, 백엔드 서버, 관리자 백오피스 UI, 세션 DR 관제실

## 1. 목적 및 배경

본 문서는 purePDFrend 하네스 거버넌스 체계에서 다음 세 가지 핵심 운영 정책을 정의합니다:
1. **재해복구 관제실(DR) UI 배치 최적화 및 시각 편의성**: 눈부심을 유발하는 원색을 배제하고, 에이전트통계 전용 화면에 정돈 배치.
2. **세션 스냅샷 파일(JSON & MD) 영속화**: 단순 DB 레코드에 국한되지 않고, 파일 시스템(`data/snapshots/`)에 직관적인 Markdown 및 JSON 파일로 보존하여 신규 AI 세션 인계 시 작업자가 즉각 미완료 상태를 식별할 수 있도록 보장.
3. **관리자 메타 거버넌스 원장 통제 체계**: 요금제, 멀티 모델 카탈로그, 사용자 계정, 실시간 쿼터 원장 동결/해제 및 수동 긴급 충전(GRANT) 거버넌스 표준화.

## 2. 재해복구 관제실 UI 및 버튼 UX 정책

1. **단독 배치 원칙**:
   - 하네스 거버넌스 도메인의 모든 하위 뷰에 일괄 표시하지 않으며, 토큰 및 사용량 정보를 관리하는 **'에이전트통계'(`usage`) 뷰 상단에만 단독 배치**합니다.
2. **시각 편의성 (Anti-Glare / Dark Slate)**:
   - `[긴급 소스 GitHub Push]` 버튼은 고채도 적색(`rose-600`)을 배제하고, 눈이 편안한 딥 슬레이트(`bg-slate-800 hover:bg-slate-700`) 배경에 은은한 엠버 펄스(`amber-400 animate-pulse`) 인디케이터를 적용하여 안정성과 시인성을 동시에 확보합니다.
3. **복구 명령 프롬프트 클립보드 복사 UX**:
   - 세션 복구는 웹 UI에서 강제 실행하는 것이 아니라, 새로운 AI 세션 대화창에서 명령 프롬프트(`#세션복구:SNAP-xxx`)를 인입하여 컨텍스트를 주입받는 절차입니다. 따라서 UI의 직접 실행 버튼을 배제하고, **원클릭 클립보드 복사 UX**로 일원화합니다.

## 3. 세션 스냅샷 파일화 및 미완료 작업 추적 정책

1. **파일 영속화 규약**:
   - 세션 스냅샷 백업 실행 시 백엔드는 즉시 두 가지 파일을 생성합니다:
     - `data/snapshots/SNAP-{timestamp}.json`: 완전한 기계 판독용 JSON 구조체 (세션, 미완료 태스크, 미완료 루프, 최신 커밋 SHA 등).
     - `data/snapshots/SNAP-{timestamp}.md`: AI 에이전트 및 작업자가 읽기 쉬운 정형화된 마크다운 보고서.
2. **미완료 잔여 작업(Residual Tasks & Loops) 명시 의무**:
   - 스냅샷 생성 시 현재 세션에서 `status_cd !== '완료'`인 태스크와 루프 목록을 별도 섹션으로 반드시 추출 및 보존해야 합니다.
3. **이중 영속화(Dual Persistence)**:
   - 파일 시스템 생성과 동시에 PostgreSQL `aiagent.harness_session_meta`의 `doc_payload.recovery_snapshot`에 동일 페이로드를 안전하게 동기화합니다.

## 4. 관리자 메타 거버넌스 백오피스 운영 정책

1. **요금제(Billing Plans) 4단계 체계**:
   - `PLAN-FREE`: 티어 1, 기본 100만 토큰, 버스트 1.0x, 초과 시 `BLOCK`.
   - `PLAN-STARTER`: 티어 3, 기본 500만 토큰, 버스트 1.2x, 초과 시 `THROTTLE`.
   - `PLAN-PRO`: 티어 7, 기본 2,000만 토큰, 버스트 1.5x, 초과 시 `PAY_AS_YOU_GO`.
   - `PLAN-ENTERPRISE`: 티어 10, 기본 5,000만 토큰, 버스트 2.0x, 초과 시 `PAY_AS_YOU_GO`.
2. **원장 동결(Freeze) 정책**:
   - 토큰 잔여량이 0 이하로 소진되거나 어뷰징 탐지 시 관리자는 실시간으로 원장을 `FROZEN` 처리할 수 있습니다.
   - 긴급 충전(GRANT) 시 잔여 쿼터가 양수로 전환되면 자동으로 동결이 해제됩니다.
3. **불변 감사 로그(QTX) 의무**:
   - 관리자의 모든 쿼터 변경(`GRANT`, `FREEZE`, `UNFREEZE`)은 `aiagent.agent_quota_transaction_log`에 사유(reason)와 함께 영구 기록되어야 합니다.
