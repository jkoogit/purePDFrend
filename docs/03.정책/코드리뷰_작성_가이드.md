## 1. 개요
본 문서는 기능 구현 후 진행되는 **보완턴(Refinement Turn)** 단계에서 개발 품질을 객관적으로 점검하고 기록하기 위한 코드리뷰 문서 작성 지침입니다.

---

## 2. 저장 위치 및 파일명 규칙
- **저장 디렉토리**: `/docs/10.리뷰/`
- **파일명 형식**: `YYMMDD_순번_작업내용.md`
  - 예시: `260917_001_바이브코딩환경_및_에이전트관리설계.md`
  - 규칙: 연도뒤 2자리(YY), 월(MM), 일(DD), 3자리 순번(001, 002...), 언더스코어 후 간결한 작업내용

---

## 3. 필수 헤더 구조 (메타데이터)
코드리뷰 문서는 반드시 최상단에 아래 10개 핵심 항목을 포함해야 합니다:

```markdown
# 코드리뷰: [작업제목]

## 📌 리뷰 메타데이터
- **작업제목**: 바이브 코딩 환경 구축 및 에이전트 관리 설계
- **작성일시**: 2026-09-17 14:00:00 KST
- **작업자**: gemini (AI Agent) / jkoogit (Human Reviewer)
- **작업AI**: Antigravity Agent
- **작업모델**: models/gemini-3.8-flash
- **작업세션**: SESSION-20260917-001
- **작업태스크**: TASK-20260917-001
- **작업내용**: OCR 엔진 설정 및 작업그래프 간격/뷰모드, 문서 18대 체계 개편
- **리뷰내용**: 레이어 결합도, 테스트 통과 여부, 타입 안전성, 예외 처리 점검
- **이슈사항**: 발견된 리팩터링 과제 또는 향후 주의점
```

---

## 4. 보완턴 체크리스트
리뷰 시 아래 항목을 충족했는지 점검하고 기록합니다:
1. **구현 테스트코드**: 단위/통합 테스트 통과 및 엣지 케이스 점검
2. **OOP 기반 DDD 설계 점검**: 도메인 모델 응집도, 불필요한 파일/코드 최소화
3. **아키텍처 적합성**: 심플 레이어 구조 유지 여부 및 헥사고날 전환 고려사항
4. **보안 점검**: 민감정보 노출 방지(API Key 등), SQL Injection / XSS 방지
5. **테스트코드 개선**: 유지보수성 높은 어서션 작성 여부
