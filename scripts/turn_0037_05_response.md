#[0037-05] 첫화면 완전 복원 및 PG-USR-08 오프라인 작업정리 실서비스 컴포넌트 분리 구현 완료 보고

사용자님의 지적과 피드백을 면밀히 분석하여, 첫화면에서 와이어프레임 검토용 컨트롤 바가 노출되던 원인을 근본 제거하고, 요청하신 **PG-USR-08 오프라인 작업정리 화면을 와이어프레임 소스로부터 실서비스 독립 컴포넌트(`OfflineTaskCleanStudio.tsx`)로 완전 분리 구현** 완료하였습니다.

---

### 1. 첫화면 이상 현상 원인 규명 및 완전 복원 조치

1. **이상 노출 원인 분석**:
   - `UnifiedServiceScreenRouter`가 37개 전체 화면 상단에 일괄적으로 `[PG-USR-01 | 첫화면(랜딩) | 실제 서비스 화면 구동 중 | 와이어프레임 원본 비교]` 안내 컨트롤 바를 상시 렌더링하도록 배치되어 있었습니다.
   - 이로 인해 엔드유저가 앱에 첫 진입했을 때 `Navbar` 아래에 라우터 컨트롤 바와 `PurePdfServicePortal`의 포털 헤더가 이중으로 중첩 표시되면서 첫화면이 마치 디버그나 와이어프레임 화면처럼 보이는 어색함이 유발되었습니다.
2. **근본 조치 완료**:
   - `UnifiedServiceScreenRouter.tsx`의 렌더링 로직을 수정하여 `currentProgId === 'PG-USR-01'`이고 와이어프레임 비교 모드가 아닐 때(`!showWireframeFallback`) 상단 라우터 바를 **100% 숨김 처리(`!isDefaultLanding`)**하도록 적용하였습니다.
   - 이제 사용자가 첫화면에 진입하면 어떠한 와이어프레임 컨트롤이나 군더더기 없이 **순수한 PDFrend 실제 서비스 랜딩 화면**만 깨끗하게 표시됩니다.
   - 메뉴 바로가기를 통해 타 프로그램(`PG-USR-02` ~ `PG-USR-09`, `PG-ADM-01` ~ `16` 등)으로 이동했을 때에만 해당 화면 상단에 프로그램 식별자와 비교 토글 스위치가 나타나며, 언제든 `[첫화면(랜딩)]` 버튼을 눌러 순수 첫화면으로 즉시 복귀할 수 있습니다.

### 2. PG-USR-08 오프라인 작업정리 실서비스 컴포넌트 독립 구현

기존 `UserWireframes.tsx`에 얽혀 있던 코드를 완전히 분리하여, 엔터프라이즈급 독립 실서비스 컴포넌트 `src/ppdf/components/OfflineTaskCleanStudio.tsx`를 신규 구축하고 통합 라우터에 직결하였습니다.

#### 📌 핵심 구현 기능 명세
| 구분 | 상세 기능 구현 내용 |
| :--- | :--- |
| **망 상태 감제** | `navigator.onLine` 실제 물리망 감지 + 시뮬레이션 토글 (`OFFLINE_CACHE_ACTIVE` vs `ONLINE_SYNC_LIVE`) |

| **히든 주석 검증** | 로컬 PDF 파일 내 각인된 메타데이터(시작/수정/종료시간, 작업자, 주석 건수) 자동 추출 및 클라우드 정본 일괄 등록 |
| **다차원 상세 필터** | 문서 ID, 문서명, 상태(충돌감지/바로머지가능/등록대기/머지완료), 작업유형, 날짜 범위(From/To), 작업자 검색 및 원터치 초기화 |
| **반응형 듀얼 뷰** | • **데스크톱**: 표준 모노스페이스 데이터 테이블 그리드 + 뷰어 열람 직결 버튼<br>• **모바일**: 정책 03-14 준수 원터치 액션 카드 레이아웃 |
| **4모드 테마 & 가드레일** | • Light / Dark / Dawn / System 4모드 토큰 완벽 대응<br>• `window.alert` 배제 비차단 애니메이션 인앱 토스트 알림 적용<br>• 결과 부재 시 일관된 정책 2.2 `"조회된 결과가 없습니다."` 보장 |

### 3. 소스 분리 및 라우터 레지스트리 현행화

1. **`src/ppdf/components/OfflineTaskCleanStudio.tsx`**: 실서비스 신규 컴포넌트 생성.
2. **`src/ppdf/index.ts`**: `OfflineTaskCleanStudio` 정식 export 등록.
3. **`src/ppdf/components/WireframeRibbonLayer.tsx`**: `PG-USR-08`(오프라인 작업 정리) 및 `PG-SET-05`(3Way 충돌머지 및 오프라인 큐)의 `targetType`을 `'service'`(실서비스 직결)로 승급 현행화.
4. **`src/ppdf/views/UnifiedServiceScreenRouter.tsx`**:
   - `hasRealServiceScreen` 목록에 `PG-USR-08`과 `PG-SET-05` 등록.
   - `renderServiceContent`에서 `OfflineTaskCleanStudio`를 기본 렌더링.
   - 기획/설계 원본 검토 필요 시 상단 `[와이어프레임 원본 비교]` 스위치로 기존 와이어프레임과 1:1 비교 검토 지원.
